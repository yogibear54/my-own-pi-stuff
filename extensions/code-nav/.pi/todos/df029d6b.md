Phase 1 complete. Changes:

**New file: `src/config.ts`**
- Typed interfaces: `ToolsConfig`, `SearchConfig`, `CodeNavToolsConfig`
- `resolveToolsConfig(raw)` — resolves raw settings with validation and defaults
- Helper functions: `positiveInt()`, `clampInt()`, `resolveNullableInt()`

**Modified: `index.ts`**
- Added `resolveAndStoreConfig()` to resolve tools+search config from settings
- Added `getConfig` getter that reads from store meta (cached per session)
- `store.setMeta("toolsConfig", ...)` called alongside existing `indexOptions` at all 3 sites (reindex, full index, incremental)
- `/code-nav-config` command now shows tools + search config values
- Passed `getConfig` to `registerTools()`

**Modified: `src/tools.ts`**
- `registerTools()` now accepts `getConfig: () => CodeNavToolsConfig` parameter
- `code_nav_definition`: uses `getConfig().tools.definitionMaxResults` (was hardcoded 20)
- `code_nav_references`: uses `getConfig().tools.referenceMaxFiles` (was 15) and `referenceMaxPerFile` (was 10)
- `code_nav_symbols`: uses `getConfig().tools.symbolSearchLimit` for workspace search (was hardcoded 50)
- `code_nav_search`: uses `config.tools.searchDefaultLimit` (was 30), `config.search.defaultScanMultiplier` (was 50), `config.search.defaultMaxCandidateFiles` (was 10000), `config.search.defaultMaxLinesScanned` (was unlimited)

No changes to `engine.ts` — the search defaults are now resolved in tools.ts and passed through to engine.ts's existing parameter-based API.
