Orchestrate the LLM through the debug lifecycle. **Reference: [docs/05-debugging-loop.md](docs/05-debugging-loop.md).**

Scope (mirrors `plan-mode`):
- `state.ts`: `{ active, mode, state, hypothesis, hypothesisCount, attempts, snippetIds, telemetryTarget }`; persist `appendEntry("debugger", state)`; restore on `session_start`.
- `skill/SKILL.md`: teaches the loop, snippet format, packet schema, when to call which tool.
- `before_agent_start`: inject `display:false` context = current state + goal + telemetry target.
- `turn_end`: advance state from tool results.
- Custom tools: `report_hypothesis`, `request_user_test`, `record_test_result`, `mark_bug_fixed`, `debug_summary`.
- 7-state machine + testing-loop protocol (hypothesis → fix → user "Bug Fixed"/"Continue" → on continue: remove fix+snippets, new hypothesis; max attempts default 3 → back to AWAITING CONTEXT).
- User affordance via `ctx.ui.select` (Bug Fixed / Continue to Debug), rendered in widget body.

Acceptance criteria: see doc §Acceptance Criteria (incl. resume-safe state, hypothesis counter, attempt cap).

Open: where `maxAttempts` is configured (default 3); "final validation" mechanics after telemetry removal.
