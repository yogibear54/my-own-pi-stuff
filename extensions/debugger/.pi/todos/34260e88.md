**Status: DONE.** `report_bug` tool registration moved from `index.ts` into `tools.ts`;
all LLM tools now live in one place. Internal refactor — no user-facing behavior
change. The `applyBug` empty-input defect was fixed in the same pass.

## Changes
- **`tools.ts`** — added `registerReportBugTool(pi, getSnapshot, applyBug)`
  containing the `report_bug` tool (schema/description/prompts moved verbatim).
  Its `execute` reuses the shared `inert()` no-session helper, coerces
  `params.summary` to a string, calls the passed-in `applyBug`, and returns
  "recorded" / "cleared (empty input.)".
- **`index.ts`** — imports + calls `registerReportBugTool(pi, () => snapshot, applyBug)`;
  removed the inline `report_bug` block; **removed the now-orphan
  `import { Type } from "typebox"`**; **fixed `applyBug`** to coerce non-string
  input (`null`/`undefined` → `""`) so it never throws and empty → clears.
- **`applyBug` + `editBug` + `paintUi`** stay in `index.ts` (decision: keep
  applyBug where the session state + the `/debugger bug` command live; pass it
  into `tools.ts` via the accessor — no state/WIDGET_KEY duplication).

## Defect fix
`applyBug` previously did `summary.trim()` and threw a TypeError on
`undefined`. Now: `const s = summary == null ? "" : String(summary);` → empty
clears (`null`), valid string stored unchanged. Verified by the harness
(`empty summary → cleared (no throw)`).

## Verification
`node snippets.tools.test.mjs` — added a `[report_bug]` section: registered;

line summary → recorded. All 4 suites green:
