Build the HTTP log server. **Reference: [docs/01-log-server.md](docs/01-log-server.md).**

Scope:
- `node:http` server on configurable port (default **8866**).
- POST → `200 {"status":"success"}`; malformed JSON → `400`; schema-invalid → `400`; non-POST → `405` (with `Allow: POST`).
- Validate against the telemetry schema (required: log_id, event_timestamp, level, source{file,line,function}, message; optional: variables, stack_trace).
- Per-session JSONL log file at `<cwd>/.pi/logs/<8-char-alphanumeric>.log` (use `CONFIG_DIR_NAME`; `mkdir -p`; one `JSON.stringify` line per packet; one file per `/debug` session).
- In-memory ring buffer (last ~500 packets) + `onPacket` callback to feed the widget.

Lifecycle: start lazily from `/debug`; close on `/debug stop` and `session_shutdown`.

Acceptance criteria: see doc §Acceptance Criteria (curl tests for 200/400/405, append behavior, dir auto-create).

Decisions baked in: port 8866 for both local & remote; JSONL-per-session.
