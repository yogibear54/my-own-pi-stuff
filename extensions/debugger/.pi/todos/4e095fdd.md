**Priority: low.** Deferred out of Part 2 (TODO-ca0bdabd). The `/debugger remote`
command is currently a stub: `arg === "remote"` is never matched in `index.ts`, so
it falls through to a local session.

**Reference: [docs/02-slash-commands.md](docs/02-slash-commands.md) → "`/debugger remote`"
section + AC2/AC3.**

## Scope (from docs/02)
1. Match `arg === "remote"` in the `debugger` command handler; do NOT fall through
   to local.
2. Verify `ngrok` is available (`pi.exec("ngrok", ["--version"])`). If missing →
   notify error with install hint and **abort (no crash)**.
3. Start `ngrok http 8866` and scrape the public URL from its output / `ngrok api`.
4. Set `snapshot.telemetryTarget` = the public ngrok URL (so injected snippets POST
   there) and surface it in the widget header.
5. Enter **instructional** mode: the agent must **not** edit the remote codebase —
   it produces copy-pasteable patches the user applies on the remote host.
   - `snapshot.mode` should flip to `"remote"` (the field already exists).
6. Notify the user with the public URL.
7. `/debugger stop` must tear down the ngrok tunnel (in addition to the server).

## Acceptance criteria (carried over from docs/02)
- AC2: `/debugger remote` starts ngrok and shows a public URL; snippets target it.
- AC3: `/debugger remote` errors gracefully (no crash) if `ngrok` is not installed.

## Open design question (pre-existing, from docs/02 Open Items)
- Remote-mode "instructional patch" format: unified diff vs fenced code block with
  file-path header. Recommend fenced code block for copy-paste ergonomics; finalize
  when this is picked up (likely depends on Part 4 snippet cleanup).

## Why low priority
Remote mode is useful but not on the critical path of the core debugging loop
(Parts 3–5). Picking it up after the state machine (Part 5) lands will also give it
a real session-state home.
